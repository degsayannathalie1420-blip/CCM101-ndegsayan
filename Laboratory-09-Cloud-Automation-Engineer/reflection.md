# Mission Reflection

This laboratory activity taught me how automation can make cloud administration easier. Performing the same task manually every day can waste time, especially when many servers are involved. By creating a Bash script, I learned how Linux commands can work together to complete a backup operation. Using cron makes the process more convenient because the script can run automatically at a scheduled time.

Automation can also cause problems when scripts contain mistakes. For example, an incorrect file path or a destructive command could affect important data. If a faulty script runs on 1,000 servers, the damage could be much greater. This is why administrators should review their scripts, test them before deployment, and check the results after execution.

A Bash script is different from a Docker Compose YAML file. Bash is used to execute commands and perform tasks, while Docker Compose defines how application containers should run and communicate. Both tools help reduce manual work and make technical processes easier to repeat.

Throughout this semester, I learned more about the different parts of cloud computing. I explored infrastructure, cloud providers, containers, storage, application deployment, server operations, security, and automation. These lessons helped me see how the different technologies work together to support applications and protect information.

The role I enjoyed most was Cloud Automation Engineer because it showed how programming can solve everyday administration problems. I learned that even a short script can save time and help prevent repeated manual work. I also realized that automation is not just about making tasks faster. It must be reliable, safe, and properly documented.

Overall, this mission improved my knowledge of Linux commands, Bash scripting, file permissions, and cron jobs. I gained a better understanding of how scheduled automation can help keep cloud operations organized and consistent.
